# Noor Jobs — Publish Kit

This package contains a publishable frontend and Supabase database schema. It is **not fully live until you connect your own Supabase project**. This setup gives real accounts, server-side account IDs, persistent applications, owner replies, and database-enforced privacy.

## 1. Create your database
1. Open https://supabase.com/ and create a project.
2. In your project, open **SQL Editor → New query**.
3. Paste all of `supabase.sql` and run it.
4. In **Project Settings → API**, copy the **Project URL** and the **anon/public key**. Never use the `service_role` key in a website.

## 2. Connect the website
1. Open `index.html` in a text editor.
2. Find `PASTE_YOUR_SUPABASE_URL_HERE` and `PASTE_YOUR_SUPABASE_ANON_KEY_HERE`.
3. Replace those two placeholders with your project URL and anon/public key.
4. Save the file.

## 3. Create your Owner account
1. Publish the site (step 4), then open it and create an account using the email you want to own the site.
2. Confirm your email if Supabase asks you to.
3. In Supabase → SQL Editor, run this, replacing the email:
   `update public.profiles set role = 'owner' where email = 'YOUR-OWNER-EMAIL-HERE';`
4. Log out and log in again. The Owner panel will now show all applicants and applications.
5. Owner password is managed through Supabase Authentication. The old demo password `nooR@` is **not** used for production login.

## 4. Publish free with Netlify Drop
1. Open https://app.netlify.com/drop
2. Drag `index.html` onto the page to deploy the frontend. (You can also upload a folder containing `index.html`.)
3. Open the generated public URL.
4. Test sign-up, login, application submission, owner reply, and applicant reply visibility.

## Important notes
- Account IDs are generated by the database identity column, not by the browser. The UI displays them with an `NJ-` prefix? The schema stores a numeric ID; the current frontend displays the raw number. You can change display formatting later if desired.
- Keep the Supabase anon key in the frontend only; it is designed to be public. Never publish database passwords or service-role keys.
- Supabase Row Level Security (RLS) policies restrict applicants to their own applications and replies; only the Owner role can read all applications and send replies.
- For a real public hiring service, configure email confirmation, password recovery, spam protection/rate limits, privacy policy, terms, and secure CV upload storage before advertising the site.
- This starter accepts a CV URL, not file uploads.
